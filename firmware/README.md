# スタックチャン・カー ファームウェア

M5Stack 製品版スタックチャン(K151 / CoreS3)を、車(逆三輪車のトライク。設計は `car/trike_design.py`、印刷データは `print_trike/`)として走らせるファームウェア。
首振り(ヨー)サーボを回し続けて後輪を回し、うなずき(ピッチ)の角度で前輪のかじを切る。
スマホのブラウザに出るジョイスティック 1 本で操作する。BLE のゲームパッド(下の「ゲームパッド」)と、M5Stack StopWatch で作るコントローラー(下の「StopWatch コントローラー」)にも対応する。

**状態: ビルドと単体テスト(`pio test -e native`、25 件)は通った。実機での走行はまだ確かめていない(2026-11-20)。**

歩行版(Strider)の操作(前進・後退ボタン、顔の上下)は、この版でなくなった。歩行版のファームウェアは git の履歴(コミット `1b84339` まで)に残っている。

## 書き込む前に

- 書き込むと、出荷時のアプリ(AI エージェントなど)は起動しなくなる。元に戻すには、下の「元に戻す」の手順でバックアップを書き戻すか、M5Burner で公式ファームウェアを書き直す。
- CoreS3 の電源を入れてからパソコンにつなぐ。「USB シリアル デバイス (COMx)」として見える(ESP32-S3 の USB-JTAG/シリアル)。

## 書き込み

**アプリ本体だけを `0x20000`(出荷時の 1 番目のアプリ領域 ota_0)に書く。** ブートローダー・領域配置・設定領域(NVS)は出荷時のまま残す。NVS にはサーボの原点調整値(名前空間 `servo`)が入っているので、消さない。

Mac では、ターミナルで実行する。スタックチャンだけを USB でつないでおく(ポートは `ls /dev/cu.usbmodem*` で見える 1 つ目を使う)。

```bash
cd firmware && pio run && ~/.platformio/penv/bin/python -m esptool --chip esp32s3 --port $(ls /dev/cu.usbmodem* | head -1) --baud 921600 write-flash 0x20000 .pio/build/stackchan/firmware.bin
```

Windows では PowerShell で実行する(Git Bash では ESP32 のツール導入が失敗する)。COM8 は実際のポート番号に置き換える。

```
cd firmware
pio run
$py = "$env:USERPROFILE\.platformio\penv\Scripts\python.exe"
& $py -m esptool --chip esp32s3 --port COM8 --baud 921600 write-flash 0x20000 .pio\build\stackchan\firmware.bin
```

ビルド済みのアプリ(`stackchan-strider-app.bin`、書き込み先 `0x20000`)は、GitHub の Releases に置く。

注意:
- `pio run -t upload` と、ビルドで出来る `firmware.factory.bin` は使わない。PlatformIO は起動スロット情報を `0xe000` に書くが、この機体の領域配置では `0xd000` にあり、ずれる。
- 出荷時の起動スロットが ota_0 であることが前提(2026-11-17 の個体では、otadata の世代番号が 3 と 2 で ota_0 が選ばれていた)。公式ファームウェアをオンライン更新した直後などで ota_1 から起動している個体では、`0x20000` に書いても出荷時アプリが起動する。その場合は otadata を初期化する(`boot_app0.bin` を `0xd000` に書く)。
- 領域配置は `partitions_stackchan.csv`(出荷時と同じ)。暗号化とセキュアブートは無効であることを確認済み。
- **書く前に、機体の領域配置を確かめる。** 前に別のファームウェアを `pio run -t upload` などで書いた機体は、出荷時と配置が違うことがある。2026-11-23 に書いた個体は、app0 が `0x10000`、otadata が `0xe000` の配置で、app0 から起動していた。この配置のときは `0x10000` に書く(`0x20000` に書くと、今のアプリの途中を上書きして起動しなくなる)。配置は、バックアップの `0x8000` にある領域表で分かる。

## 元に戻す

**書き込む前に、自分の機体の出荷時の内容(16MB)を丸ごと読み出して保存しておく。** 数分かかる。

```
& $py -m esptool --chip esp32s3 --port COM8 --baud 921600 read-flash 0x0 0x1000000 backup\stackchan_factory_flash_16MB.bin
```

Mac では次のとおり(`firmware` フォルダで実行):

```bash
mkdir -p backup && ~/.platformio/penv/bin/python -m esptool --chip esp32s3 --port $(ls /dev/cu.usbmodem* | head -1) --baud 921600 read-flash 0x0 0x1000000 backup/stackchan_flash_16MB.bin
```

元に戻すときは、保存したファイルを先頭から書き戻す。Mac では:

```bash
~/.platformio/penv/bin/python -m esptool --chip esp32s3 --port $(ls /dev/cu.usbmodem* | head -1) --baud 921600 write-flash 0x0 backup/stackchan_flash_16MB.bin
```

Windows では:

```
& $py -m esptool --chip esp32s3 --port COM8 --baud 921600 write-flash 0x0 backup\stackchan_factory_flash_16MB.bin
```

バックアップには、その機体の設定(保存済みの Wi-Fi など)が入りうるので、人に渡したり公開したりしない。

## 使い方

1. **はじめて起動したとき**: 画面に QR が 1 つ出る(「Wi-Fi の設定 1 / 2」)。スマホのカメラで読んで設定用 Wi-Fi(`Strider-XXXX`)につなぐ。
2. スマホに設定ページがポップアップで開く(「キャプティブ…」という名前の画面)。開かないときは、スタックチャンの画面が「2 / 2」に切り替わっているので、その QR を読む。
3. 家の Wi-Fi を選び、パスワードを入れて「この Wi-Fi につなぐ」を押す。同じ名前で 2.4GHz と 5GHz を出しているルーターなら、そのまま選べばよい(本体は 2.4GHz 側につながる)。
4. 本体が再起動して家の Wi-Fi につながると、画面に**操作ページの QR** が出る。スマホは自動で家の Wi-Fi に戻るので、そのまま読む。ページが開くと画面は顔に戻る。`http://strider.local/` でも開ける場合がある。

操作ページ:

| 操作 | 動き |
|---|---|
| 丸いジョイスティックのつまみを上下に動かす | 上で前進、下で後退。倒すほど速い(10〜60%)。真ん中付近(±10%)は止まる |
| つまみを左右に動かす | かじを切る。右いっぱいでうなずき 30°、左いっぱいで 0°。真ん中で直進の角度 |
| 指を離す | 止まって、前輪がまっすぐに戻る |
| 設定 → 車の種類 | 「car500」(直進 12.6°)、「レトロカー」(13.0°)、「トライク」(15.0°)。本体に保存する。トライクは後輪でかじを取るので、スティックの左右とうなずきの向きの関係を逆にする(微調整のボタンの向きも合わせて逆になる) |
| 設定 → 微調整「← 左へ」「右へ →」 | 直進の角度を 0.5° ずつ動かす(5〜25°)。まっすぐ進めて左へ曲がるなら「右へ」 |
| 設定 → 前進と後退を入れ替える | つまみを上へ動かして後ろへ進むときにチェック |
| 設定 → 走っている間は笑顔にする | 初期状態は OFF |
| 設定 → ゲームパッドを登録し直す | 登録(ボンド)を消して、パッドを探し直す |
| 設定 → Wi-Fi の設定をやり直す | 2 回押すと設定を消して最初の画面に戻る |

本体:

| 操作 | 動き |
|---|---|
| 頭の上をさわって離す | 操作ページの QR をもう一度出す(15 秒たつか、ページが開かれると顔に戻る。残り秒数を画面に出す) |
| 頭の上を 5 秒さわり続ける | 画面に「Wi-Fi の設定を消しますか?」と出る。画面の「消す」をタッチしたときだけ消して再起動する。「やめる」か 10 秒放置で顔に戻る |

つまみに触れている間は、スマホから 0.1 秒ごとに値を送る。0.9 秒途切れると本体が自動で止まる(離した合図が届かなかった、電波が切れた、など)。画面を切り替えたときも止める。値にはひと押しごとの番号を付け、離したあとに遅れて届いた値で走り出さないようにしている。

**うなずきは 0〜30° に必ず収める。** 本体の側でも制限している(`src/car_control.h` の `PITCH_MAX_DEG`)。30° を超えると引き棒やフェンダーが当たる。

## ゲームパッド(BLE)

スタックチャン(ESP32-S3)は **BLE にしか対応しない。Bluetooth Classic のパッドはつながらない。**

| パッド | つながるか |
|---|---|
| Switch(初代)の Pro コン、PS4 / PS5、8BitDo の全機種 | ✕ Classic |
| HD-6500(手持ち) | ✕ どのモードでも Classic だった(Mac で Xbox One S の Classic 版 PID 02E0、Fire TV 用パッド 1949:0402 として見えた) |
| Xbox ワイヤレス コントローラー(ファームウェア v5.15 以降) | ◯ のはず(未確認)。記述子は HD-6500 と同じ形で、テストで読めることを確かめた |
| Switch 2 の Pro コン、Steam Controller | △ BLE だが独自の通信で、今のコードでは読めない |

つなぎ方(BLE のパッドを用意したとき):

1. スタックチャンを起動しておく(Wi-Fi の設定の前でもよい)。
2. パッドをペアリング待ちにする。本体は HID サービス(`0x1812`)を出している機器を探し、つないで登録(ボンド)する。
3. つながると、顔の吹き出しに「Pad OK」と出る。操作ページにも「ゲームパッド: つながっています」と出る。
4. 左スティックで、スマホのジョイスティックと同じ操作ができる。スティックが倒れている間は、スマホからの操作より優先する。
5. 次からは、パッドの電源を入れるだけで自動でつながる。パッドが切れると(約 0.5 秒で検出)、止まって前輪がまっすぐに戻る。

機種ごとの作り込みはしない。パッドの HID 記述子(Report Map)を読み、左スティックの X / Y の位置と範囲を取り出す(`src/hid_parser.cpp`)。つないだときに、記述子を 16 進でシリアルに出す(115200 bps)。うまく読めない機種は、それをテスト(`test/test_hid_parser/`)に足して直す。

## StopWatch コントローラー

M5Stack StopWatch(C152、ESP32-S3、電池 450mAh)を、手に持つ専用のコントローラーにする。配線はいらない。画面のタッチか、本体の傾きで操作する。ESP-NOW(ESP32 どうしの直接の通信)で、スタックチャンに操作の値を 0.05 秒ごとに送る。ルーターを通さないので、家の外(設定用 Wi-Fi の状態)でも使える。ソースは `src/controller/`。

**状態: StopWatch とスタックチャンが組になり、スタックチャンを再起動しても自動でつながり直すことを、シリアルの記録で確かめた(家の Wi-Fi は 12ch。つながり直すまで約 8 秒)。車輪を浮かせて、タッチで前進・後退できることを、電源を入れ直したあとにも確かめた。傾きの操作はまだ(2026-11-23)。**

### 書き込み

StopWatch だけを USB でつなぐ。中身は上書きされる。先に出荷時の中身を丸ごと読み出して保存しておく(上の「元に戻す」と同じ手順。ポートは StopWatch のもの)。

```bash
cd firmware && pio run -e controller_stopwatch -t upload
```

### 使い方

1. **はじめて組にする:** スタックチャンを起動しておき、StopWatch を起動する。画面が「Pairing」から「Linked」に変わり、スタックチャンの顔に「Atom OK」と出れば組になった。スタックチャンは、登録がない間、最初に申し込んできたコントローラーを登録する。
2. **組にしたあと:** スタックチャンを再起動する。コントローラーを登録してあると BLE のゲームパッドを探さなくなり、Wi-Fi の受信が速くなる(BLE と Wi-Fi を同時に使うと、Wi-Fi の省電力の待ち受けを止められない)。
3. 次からは、両方の電源を入れるだけでつながる。スタックチャンの Wi-Fi のチャンネルに合わせて、StopWatch がチャンネルを自動で探す(最大で数秒)。

| 操作 | 動き |
|---|---|
| タッチのとき: 画面を指でなぞる | 画面の中心からのずれで進む。上で前進、左右でかじ。指を離すと止まる |
| 傾きのとき: 黄のボタンを押したまま傾ける | 押した瞬間の姿勢から、奥へ傾けると前進、左右に傾けるとかじ(25° で最大)。ボタンを離すと止まる |
| 青のボタンを押して離す | タッチと傾きを切り替える(本体に保存) |
| 青のボタンを 3 秒押す | 登録を消して、組にする相手を探し直す |
| 操作ページの「Atom を登録し直す」 | スタックチャン側の登録を消す。60 秒の間に、電源の入っているコントローラー(前と同じものでも)を新しく登録する。BLE のゲームパッドに戻すときは、押したあと本体を再起動する |

- コントローラーの値が 0.5 秒途切れると、スタックチャンは止まる。
- スタックチャンは、登録したコントローラーからの値だけを使う。
- 傾きの向きが逆なら、`src/controller/input_stopwatch.cpp` の `TILT_INVERT_X`・`TILT_INVERT_Y` を変える。傾きのときは、画面の下に傾き(R と P、単位 °)が出る。
- USB につなぐと、2 秒ごとに状態をシリアルに出す(`[ctl] board=30 paired=… ch=… linked=… x=… y=…`)。

## 初回の確認(車輪を浮かせて)

1. 起動したとき、首(うなずき)が直進の角度(トライクで 15.0°)になるか。首(ヨー)が勝手に回らないか。
2. スマホのジョイスティックを左右に動かすと、前輪が左右に切れるか。右いっぱいでも 30° を超えず、引き棒やフェンダーに当たらないか。
3. 上下に動かすと後輪が回るか。指を離すと止まり、前輪がまっすぐに戻るか。
4. 上に動かして後ろへ進むなら、「前進と後退を入れ替える」にチェックする。
5. 床に置いてまっすぐ進め、曲がるなら微調整で直す。
6. 走っている間にスマホの Wi-Fi を切ると、1 秒ほどで止まるか。
7. **スマホの操作が遅れないか(パッドがなくても確かめる)。** 本体はパッドをずっと探していて、電波を Wi-Fi と共用している(探す時間は 3 割に絞ってある)。遅れるときは、`src/main.cpp` の `gamepad::begin();` の行を消して書き込み直すと、パッドを探さなくなる。
8. (BLE のパッドがあれば)つながるか。電源を切ると止まるか。再起動のあと自動でつながり直すか。

## 設計上の決めごと

- 画面の向きは指定しない。この機体(M5Unified のボード番号 27)は初期状態で向き 0・横 320 × 縦 240 で、`setRotation(1)` を入れると 90° 回る。
- **首(ヨー)を連続回転モードにするのは、起動から 2 秒たってから。** 公式ライブラリは、最初の `rotateX` のときに 1 回だけモードを切り替える。電源を入れた直後はサーボがまだ応えず、切り替えに失敗しても「切り替えた」と記録するので、二度と回らなくなる(書き込み後の再起動ではサーボの電源が切れないので、この不具合は出ない)。
- **首(ヨー)は連続回転だけで動かす。** 公式ライブラリの `Motion.stop()`・`goHome()`・`moveX()` は首を角度指定に戻す実装で、土台が回り続けるこの機体では原点の角度まで首を回そうとして脚が動く。止めるときは `rotateX(0)`(出力 0)にしている。
- 速さの上限は 60%(歩行版のシミュレーションで、全開だと跳ねて進みが悪かった値をそのまま使う)。
- うなずきの命令は、0.5° 以上変わったときだけ、最短 50 ms の間隔で送る。サーボとの通信を詰まらせないため。
- パッドを探す・つなぐ処理は専用のタスク(コア 0)で行い、`loop()` を止めない。パッドは値が変わったときしか送ってこないので、「途切れたら止める」は使えず、切断の検出(supervision timeout 0.5 秒)で止める。
- 顔の描画を止めるときは `avatar.stop()` を使い、描画ループが終わるまで 200 ms 待つ。`suspend()` は描画タスクを画面への通信の途中で凍結しうるので使わない。
- 家の Wi-Fi のパスワードは本体の NVS(`strider` 名前空間)にだけ保存する。設定用 Wi-Fi はパスワードなしで、設定が終わると出なくなる。
- 操作ページに認証は無い。同じ Wi-Fi につながっている人は誰でも操作できる。

## ビルド環境

- PlatformIO + pioarduino(Arduino-ESP32 3 系)。公式の StackChan-BSP が ESP-IDF 5 の API を使うため、PlatformIO 標準の環境(2 系)ではコンパイルできない。
- 依存: StackChan-BSP 1.1.1(コミット e2f3b02)、M5Unified 0.3.0、M5GFX 0.3.0、M5Stack-Avatar 0.10.0、IRremoteESP8266、M5Unit-NFC、NimBLE-Arduino 2.5.2。
- アプリの大きさは 1.93 MB(ota_0 の 37%)。
- `src/main.cpp`(動作)、`src/pages.h`(スマホに出す設定ページと操作ページ)、`src/car_control.*`(スティック → 速さとうなずき)、`src/gamepad.*`(BLE パッド)、`src/hid_parser.*`(HID 記述子の読み取り)。
- 単体テスト: `pio test -e native`(機器に依存しない `hid_parser` と `car_control`)。
